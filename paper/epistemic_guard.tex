\section{Introduction}
\label{sec:intro}

Software engineering and operations agents invoke external tools over JSON-RPC transports such as the Model Context Protocol (MCP)~\cite{mcp2025spec}. MCP standardizes wire transport, not post-call truthfulness: what happened on the wire can diverge from what the language model tells the user or writes to persistent state. In live agent loops, tool calls return HTTP errors, time out, fail schema checks, or never run at all while the model claims in first-person prose that the action succeeded~\cite{maxwell2026evasion}. When downstream workflows or memory stores ingest those unverified claims, single-turn hallucinations persist across sessions~\cite{greshake2023indirect,maxwell2026poisoning}.

From a runtime verification perspective~\cite{leucker2009brief,bartocci2018lectures}, closing this gap without trusting the agent's own address space or reserving GPU memory requires three checks across each turn:
\begin{enumerate}
  \item \textbf{Out-of-Process Execution Receipts:} Every MCP tool call and response must be signed outside the agent process, separating pre-execution rejection (\texttt{executed=false}) from runtime tool failure (\texttt{executed=true, ok=false}).
  \item \textbf{Receipt-Bound Prose Supervision:} Before an assistant reply reaches the user or an orchestrator, state-mutating claims in natural language must match verified execution receipts from the current turn.
  \item \textbf{Provenance-Gated Storage and De-Syndicated RAG:} Persistent memory stores must reject unsigned or narration-sourced writes at the database boundary, and retrieval-augmented generation (RAG) pipelines must collapse mirrored web copies before counting independent sources on high-hazard queries.
\end{enumerate}

These failure modes correspond to three entries in the OWASP Top 10 for Agentic Applications~\cite{owasp2026agentic}: Tool Misuse and Unverified Action Claims (\texttt{ASI02}), Memory and Context Poisoning (\texttt{ASI06}), and Cascading Inter-Component Hallucinations (\texttt{ASI08}). Existing open-source tools cover separate parts of this path. Transport firewalls such as Pipelock~\cite{pipelock2026} scan MCP egress traffic and emit mediator-signed receipts, and runtimes such as NabaOS~\cite{nabaos2026} enforce Ed25519-signed policy constitutions, but neither checks post-turn prose against tool receipts nor deduplicates syndicated RAG sources before memory writes. Dialogue guardrails such as NeMo Guardrails~\cite{rebedea2023nemo}, Llama Guard~\cite{inan2023llamaguard}, and Guardrails AI~\cite{guardrailsai2024} filter text with dialogue rules or LLM judges that consume \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L50}{8,844}--\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L66}{12,214}\,MiB of GPU VRAM and do not verify cryptographic tool receipts.

This paper describes the architecture, security invariants, and empirical evaluation of \texttt{epistemic-guard} (v0.5.1), a Python runtime verification library and MCP proxy~\cite{maxwell2026seed,maxwell2026fivelayer}. Its main components are:
\begin{itemize}
  \item \textbf{Out-of-Process MCP Receipt Proxy (\texttt{mcp-proxy}):} A \texttt{stdio} JSON-RPC\,2.0 proxy that strips signing secrets from child server environments, classifies \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table2_conformance.json\#L13}{4} execution and error states, appends Ed25519-signed receipts to an OS-locked JSONL Merkle log with public-key pinning, and translates bidirectionally to the Agent Execution Receipt (\texttt{AER-1}) format~\cite{zambo2026aer1}.
  \item \textbf{CPU INT8 Receipt Supervision:} A hybrid symbolic--neural supervisor (\texttt{ReceiptSupervisor}) backed by \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L10}{4} OpenVINO INT8 encoders (\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L28}{279.48}\,MB on disk, \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L32}{0}\,MiB GPU VRAM) plus receipt signature and target matching, running in \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L34}{27.38}\,ms median CPU latency.
  \item \textbf{Provenance-Gated SQLite Store \& RAG Mirror Filter:} Domain-separated HKDF-SHA256~\cite{krawczyk2010rfc5869} + Ed25519~\cite{josefsson2017rfc8032} write-gating with SQLite immutability triggers, paired with word-shingle Jaccard and SimHash clustering~\cite{broder1997resemblance,charikar2002similarity} across a \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L20}{12}-cell hazard-by-proof-standard policy table.
  \item \textbf{Reproducible Benchmarks:} Deterministic test scripts audited with \texttt{osaudit}, tying every reported number in this paper to SHA-256 input hashes and checked-in JSON outputs.
\end{itemize}

\section{Threat Model and Verification Scope}
\label{sec:threat}

\paragraph{System Model.}
An agent process $\mathcal{A}$ interacts with external MCP tool servers $\{\mathcal{S}_1, \dots, \mathcal{S}_k\}$, a web/RAG retrieval pipeline $\mathcal{R}$, and a local memory database $\mathcal{M}$. On turn $t$, $\mathcal{A}$ sends zero or more JSON-RPC\,2.0 \texttt{tools/call} requests, receives responses or transport errors, optionally retrieves external web pages, writes candidate facts to $\mathcal{M}$, and returns a natural-language reply $y_t$.

\paragraph{Adversary and Fault Assumptions.}
We consider both stochastic model failures and adversarial indirect prompt injections~\cite{greshake2023indirect} embedded inside tool outputs or retrieved web documents:
\begin{enumerate}
  \item \emph{In-process agent untrustworthiness (\texttt{ASI02}, \texttt{ASI08}):} The agent process $\mathcal{A}$ (or injected prompt context controlling $\mathcal{A}$'s generation) may claim in $y_t$ that a side-effecting tool call succeeded when no call occurred, when the server returned \texttt{isError=true}, or when the child process crashed mid-flight. If signing keys reside inside $\mathcal{A}$'s environment variables or memory space, compromised code or tool plugins sharing that process could forge execution receipts.
  \item \emph{Cross-session memory poisoning (\texttt{ASI06}):} $\mathcal{A}$ may attempt to persist unverified assistant narration (\texttt{LLM\_NARRATION}) or untrusted tool/web text (\texttt{TOOL\_CONTENT\_UNTRUSTED}) into $\mathcal{M}$ as verified facts, or mutate historical audit rows via SQL \texttt{UPDATE}/\texttt{DELETE} statements.
  \item \emph{Syndicated corroboration spoofing (\texttt{ASI06}, \texttt{ASI08}):} Retrieved web pages frequently reproduce identical wire-service copy, scraped documentation, or coordinated SEO mirrors across distinct hostnames. Naive multi-URL counting treats \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table2_conformance.json\#L49}{3} mirrors of a single rumor as independent corroboration for high-hazard medical, financial, or security claims.
\end{enumerate}

\paragraph{Trusted Computing Base (TCB) and Non-Goals.}
The TCB comprises the host OS kernel, the out-of-process \texttt{epistemic-guard mcp-proxy} process holding the signing key, the pinned SHA-256 digests of the \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L19}{16} INT8 model files, and OS file permissions on the SQLite database and pinned public key. We do \emph{not} defend against host kernel compromise, verify whether an external API returned HTTP 200 while silently failing internally, or replace network egress allowlists (\texttt{epistemic-guard} can run behind egress proxies such as Pipelock~\cite{pipelock2026}).

\subsection{Domain-Separated Cryptographic Provenance and AER-1 Receipts}
\label{sec:crypto}

Rather than sharing one symmetric key across components, \texttt{provenance.py} derives \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L8}{5} domain-isolated Ed25519~\cite{josefsson2017rfc8032} keypairs (\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L3}{32}-byte keys, \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L4}{64}-byte signatures) from a master seed via RFC\,5869 HKDF-SHA256~\cite{krawczyk2010rfc5869} across \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L22}{7} provenance domains (\texttt{Provenance}): \texttt{USER\_\allowbreak EXPLICIT}, \texttt{USER\_\allowbreak CONFIRMED}, \texttt{TOOL\_\allowbreak VERIFIED}, \texttt{LISP\_\allowbreak ASSERTION}, \texttt{INFERRED}, \texttt{LLM\_\allowbreak NARRATION}, and \texttt{TOOL\_\allowbreak CONTENT\_\allowbreak UNTRUSTED}. \texttt{Signer\allowbreak Factory} provides no signing constructor for \texttt{LLM\_\allowbreak NARRATION} or \texttt{TOOL\_\allowbreak CONTENT\_\allowbreak UNTRUSTED}, so model prose and untrusted tool text cannot produce a signed envelope through the public API.

Each tool call produces a canonical \texttt{Tool\allowbreak Receipt} containing the call ID, tool name, structured arguments, SHA-256 output digest, execution flag (\texttt{executed}), outcome flag (\texttt{ok}), error code, optional session ID, UTC timestamp, and detached Ed25519 signature. Receipts append into an RFC\,6962~\cite{laurie2013rfc6962} domain-separated Merkle tree (\texttt{0x00} leaf prefix, \texttt{0x01} interior node prefix) with logarithmic inclusion proofs and path-side geometry checks. For cross-tool interoperability, \texttt{Tool\allowbreak Receipt.\allowbreak to\_\allowbreak aer1} and \texttt{Tool\allowbreak Receipt.\allowbreak from\_\allowbreak aer1} convert to and from the \texttt{AER-1} (\texttt{draft-zambo-aer1}) receipt format~\cite{zambo2026aer1}, committing execution state, input arguments, call/session IDs, and SHA-256 input/output digests while keeping detached Ed25519 signatures in the enclosing receipt and \texttt{Receipt\allowbreak Log\allowbreak Entry}.

\subsection{Out-of-Process \texttt{stdio} MCP Receipt Proxy}
\label{sec:proxy}

In-process Python decorators (\texttt{Receipt\allowbreak Recorder}) protect benign agent loops against hallucinated actions, but share memory and environment variables with the agent runtime. For untrusted or prompt-injected runtimes, \texttt{epistemic-guard mcp-proxy} interposes as an out-of-process \texttt{stdio} parent between the MCP host (e.g., Claude Desktop, Cursor, or custom MCP clients) and any downstream MCP tool server:
\begin{enumerate}
  \item \textbf{Secret Scrubbing:} Before spawning the child MCP server, \texttt{mcp-proxy} case-insensitively strips signing-secret environment variables (including \texttt{EPISTEMIC\_\allowbreak GUARD\_\allowbreak MASTER\_\allowbreak KEY} and \texttt{EPISTEMIC\_\allowbreak GUARD\_\allowbreak MCP\_\allowbreak KEY\_\allowbreak HEX}) from the child's environment block so compromised child servers cannot forge receipts.
  \item \textbf{Four-State Wire Classification:} As JSON-RPC\,2.0 frames stream over \texttt{stdin}/\texttt{stdout}, \texttt{mcp-proxy} correlates \texttt{tools/call} requests in FIFO order per JSON-RPC \texttt{id} and distinguishes \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table2_conformance.json\#L13}{4} runtime outcomes: (a) normal tool completion (\texttt{executed=true, ok=true}); (b) application-level MCP tool failure where \texttt{result.isError=true} (\texttt{executed=true, ok=false, mcp\_\allowbreak tool\_\allowbreak error}); (c) pre-execution JSON-RPC parameter or schema validation rejection (\texttt{executed=false, ok=false}); and (d) child server crash or EOF mid-call (\texttt{executed=true, ok=false, mcp\_\allowbreak server\_\allowbreak eof}), recorded as failed so post-turn prose cannot claim completion.
  \item \textbf{Key-Pinned Append-Only Audit Log:} Signed entries bind a session identifier, Ed25519 public key, and UTC timestamp, acquire cross-process OS file locks for multi-worker concurrency, chain optionally across rotated Ed25519 keys (\texttt{-{-}prev-log}), and flush immediately to an append-only JSONL Merkle log; \texttt{verify-log} (with optional external \texttt{-{-}pubkey-file} pinning) rejects payload mutation, cross-session replay, and key-substitution attacks, while \texttt{attach\_\allowbreak otel\_\allowbreak evidence} exports cryptographic receipt digests to OpenTelemetry traces.
\end{enumerate}
In addition to \texttt{mcp-proxy}, \texttt{epistemic-guard mcp-server} exposes \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L11}{4} verification tools directly over MCP across \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L25}{3} protocol revisions (\texttt{2024-11-05}, \texttt{2025-03-26}, and \texttt{2025-06-18}).

\subsection{Hybrid Symbolic--Neural Post-Turn Prose Supervision}
\label{sec:supervision}

Regex-only action supervisors suffer high false negatives when models paraphrase state mutations using indirect phrasing, nominalizations, or passive voice, whereas pure zero-shot NLI encoders suffer low recall and high false positives on conversational statements~\cite{maxwell2026evasion}. Across its runtime verification and RAG corroboration pipeline, \texttt{epistemic-guard} ships \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L10}{4} OpenVINO INT8 models (\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L19}{16} SHA-256-pinned files totaling \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L28}{279.48}\,MB, distributed via Hugging Face Hub with GitHub Releases fallback). For post-turn action checking, \texttt{ReceiptSupervisor} executes a two-stage CPU pipeline:
\begin{enumerate}
  \item \textbf{Speech-Act Action-Claim Detection:} Non-assertive spans (negations, conditionals, attributed quotes, and fenced code blocks) are masked while structured \texttt{[ACTION: verb target]} (\texttt{SOAC}) tags are extracted, and candidate clauses are scored by the fine-tuned INT8 \texttt{action\_claim} cross-encoder (\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L13}{82.67}\,MB). If no completed external side effect is asserted, the turn passes immediately without requiring receipts.
  \item \textbf{Cryptographic Receipt \& Target Matching:} When a side-effect claim is detected, \texttt{Receipt\allowbreak Supervisor} verifies the turn's \texttt{Tool\allowbreak Receipt} set via \texttt{Provenance\allowbreak Gate} (enforcing Ed25519 signatures, session binding, and receipt-age bounds when configured), excludes any receipt with \texttt{executed=false} or \texttt{ok=false}, and matches claimed action families, additive claim counts, and concrete file/URL/identifier targets against verified receipt arguments. Ungrounded claims return \texttt{Supervision\allowbreak Verdict(\allowbreak is\_valid=false)} with exact character-offset spans and \texttt{to\_\allowbreak retry\_\allowbreak prompt()} remediation guidance.
\end{enumerate}

\subsection{Provenance-Gated SQLite Memory and De-Syndicated RAG}
\label{sec:memory}

\paragraph{Storage-Boundary Write Gate.}
In \texttt{store.py}, \texttt{SQLite\allowbreak Provenance\allowbreak Store} wraps SQLite WAL persistence behind mandatory \texttt{ProvenanceGate} verification and serialized \texttt{BEGIN IMMEDIATE} write transactions. Only \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L5}{5} provenance domains with valid detached Ed25519 signatures are write-eligible; writes carrying \texttt{LLM\_NARRATION}, \texttt{TOOL\_\allowbreak CONTENT\_\allowbreak UNTRUSTED}, forged keys, or mutated payloads raise \texttt{ProvenanceError} or \texttt{Signature\allowbreak Tamper\allowbreak Error} before touching SQLite. Accepted envelopes are linked into a cumulative SHA-256 chain digest and protected by \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table2_conformance.json\#L34}{2} SQL \texttt{BEFORE UPDATE} and \texttt{BEFORE DELETE} triggers that abort in-place mutation of committed provenance records.

\paragraph{Syndication Deduplication and Hazard-Tiered Corroboration.}
Before web-retrieved claims are promoted into \texttt{INFERRED} memory or stated without hedging, \texttt{corroboration.py} shards candidate passages into word shingles of width $k=\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L23}{4}$, drops non-evidentiary boilerplate with the MiniLM~\cite{wang2020minilm} INT8 \texttt{web\_evidence} encoder (\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L16}{23.06}\,MB), checks cross-source contradictions with the DeBERTa-v3~\cite{he2023debertav3} INT8 \texttt{nli} cross-encoder (\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L15}{91.1}\,MB), and merges near-duplicate mirrors via shingle Jaccard resemblance~\cite{broder1997resemblance}, SimHash fingerprints~\cite{charikar2002similarity}, and registrable-domain grouping. Independent source counts are checked against \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L2}{4} consumer action contexts and a \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L7}{3}-tier hazard classifier (\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L14}{82.65}\,MB; \texttt{LOW}, \texttt{MEDIUM}, \texttt{HIGH}) mapped onto \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L21}{4} proof standards (\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L20}{12} policy cells). High-hazard claims supported only by syndicated copies of one origin collapse to a single cluster and fail the corroboration check.

\section{Empirical Evaluation}
\label{sec:eval}

We structure our evaluation around two research questions:
\begin{itemize}
  \item \textbf{RQ1 (Cryptographic \& Wire-Protocol Conformance):} Do the Merkle receipt ledger, \texttt{AER-1} interop layer, out-of-process \texttt{mcp-proxy} fault classifier, SQLite provenance gate, and RAG syndication filter uphold their security invariants with zero false accepts and zero secret leakage under adversarial fault injection?
  \item \textbf{RQ2 (Held-Out Prose Supervision Accuracy \& Resource Cost):} How accurately and rapidly does \texttt{ReceiptSupervisor} detect ungrounded post-turn action claims on held-out traces compared with 12B--14B parameter GPU LLM judges and pure CPU NLI baselines?
\end{itemize}

All experiments are deterministic, version-pinned, and audited with \texttt{osaudit} manifests under \texttt{results/} (\texttt{table1\_\allowbreak architecture.json}, \texttt{table2\_\allowbreak conformance.json}, and \texttt{table3\_\allowbreak heldout\_\allowbreak supervision.json}). Confidence intervals for binomial proportions use the two-sided \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/osaudit.toml}{95\%} Wilson score interval~\cite{wilson1927probable}.

\section{Limitations and Threats to Validity}
\label{sec:limitations}

\paragraph{Internal Validity.}
Protocol conformance workloads in Table~\ref{tab:conformance} run real child processes, Ed25519/HKDF signing, and OpenVINO INT8 inference, using deterministic local payloads rather than live SaaS endpoints so auditors can run \texttt{osaudit results -{-}rerun} offline without API keys or network variance.

\paragraph{External Validity.}
Our held-out supervision benchmark ($N=\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L59}{250}$) tests English assistant replies across software engineering, productivity, and state-mutation tools. Non-English text, code-only diffs without prose, or domain-specific idioms outside standard tool-use patterns may show higher error rates (\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L29}{4} false negatives and \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L30}{10} false positives on our English held-out splits).

\paragraph{Construct and Transport Scope.}
First, \texttt{mcp-proxy} in v0.5.1 mediates \texttt{stdio} MCP servers; Streamable HTTP/SSE remote servers require a local \texttt{stdio} bridge or in-process \texttt{ReceiptRecorder} wrapping. Second, receipts prove only that a downstream server returned \texttt{ok=true} with a given output digest; they cannot verify whether an external API lied about performing an internal write. Third, word-shingle Jaccard and SimHash clustering ($k=\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table1_architecture.json\#L23}{4}$) collapses verbatim and lightly edited wire copy, whereas heavily paraphrased rewrites of one rumor with low word overlap can evade shingling and require source-reputation filters.

\section{Related Work}
\label{sec:related}

\paragraph{MCP Firewalls and Cryptographic Agent Runtimes.}
Pipelock~\cite{pipelock2026} is an open-source Go egress proxy and MCP firewall that scans outbound tool parameters for prompt injection or data leaks and emits Ed25519 receipts in \texttt{AER-1} format~\cite{zambo2026aer1}. NabaOS~\cite{nabaos2026} runs agents inside OS sandboxes governed by Ed25519-signed YAML constitutions. Pipelock inspects traffic before execution; \texttt{epistemic-guard} imports and exports \texttt{AER-1} receipts while checking post-turn prose (\texttt{ReceiptSupervisor}), gating SQLite memory writes, and collapsing syndicated RAG sources.

\paragraph{Conversational Guardrails and LLM-as-a-Judge.}
NeMo Guardrails~\cite{rebedea2023nemo} executes Colang dialogue rails; Llama Guard~\cite{inan2023llamaguard} fine-tunes multi-billion-parameter classifiers for safety moderation; and Guardrails AI~\cite{guardrailsai2024} chains structural and semantic validators. Rather than moderating toxicity or running an \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L50}{8,844}--\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L66}{12,214}\,MiB GPU judge, \texttt{epistemic-guard} checks whether user-facing prose matches signed wire receipts in \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L32}{0}\,MiB VRAM.

\paragraph{Classical Runtime Verification and Provenance Security.}
Runtime verification monitors execution traces against formal properties~\cite{leucker2009brief,bartocci2018lectures}, and Certificate Transparency~\cite{laurie2013rfc6962} introduced append-only Merkle audit logs for untrusted intermediaries. Work on indirect prompt injection~\cite{greshake2023indirect} and agent memory poisoning~\cite{maxwell2026poisoning,maxwell2026fivelayer} shows that mixing untrusted text and verified execution state in one memory store enables cross-session compromise (\texttt{ASI06}~\cite{owasp2026agentic}). \texttt{epistemic-guard} applies out-of-process monitor separation and RFC\,6962 Merkle logs directly to Python tools and \texttt{stdio} MCP servers.

\section{Conclusion}
\label{sec:conclusion}

\texttt{epistemic-guard} (v0.5.1) combines an out-of-process \texttt{stdio} MCP receipt proxy, OpenVINO INT8 prose supervision, Ed25519-gated SQLite storage, and RAG mirror deduplication. Keeping signing keys outside the agent process and checking prose claims against RFC\,6962 and \texttt{AER-1} receipts catches ungrounded side-effect claims at \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L23}{94.4\%} held-out accuracy (\href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L40}{96.72\%} recall) and blocks \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table2_conformance.json\#L40}{100.0\%} of unauthorized memory writes on CPU at \href{https://github.com/AlienatedAliens/epistemic-guard/blob/v0.5.1/results/table3_heldout_supervision.json\#L33}{29.43}\,ms mean latency. Next steps include Streamable HTTP transport support in \texttt{mcp-proxy} and cross-lingual paraphrase clustering in \texttt{corroboration.py}.
